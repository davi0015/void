**Fixes**

- A chat keeps the model it was using. The dropdown is global state, and a thread's
  saved selection was only written when a message was sent, or when the model was
  changed *while that thread was current* — so a thread that had never sent a
  message, or was written before the field existed, had nothing to restore, and
  returning to it kept whatever had been picked in another tab. The selection is now
  written when the thread is left, at the single state transition every switch goes
  through, so `new chat → pick a model → go back` lands on that thread's own model,
  and the write cannot be lost to a caller's stale copy of the thread list (#172)

- Settings stop reverting a moment after they are set. Every settings write replaced
  the whole JSON blob with a copy read earlier, so a second window — or the same
  window's own storage echo — reverted keys the writer never touched. A three-way
  merge now compares what this writer last read (`base`), what it is about to write
  (`ours`) and what storage holds, and only a locally changed key wins; a deletion
  is compared too, so the persisted blob cannot resurrect a removed key. The pinned
  tabs and last-active maps use the same merge (`common/storageMerge.ts`) (#175)

- A temporary terminal returns output that arrives after the command's start marker.
  The shell integration reports a command finished *during* the parse of a chunk,
  while `onData` for that same chunk fires afterwards — and the output tracker was fed
  from `onData`. A process with startup cost (`node`) puts its output and the `D`
  marker in the same late chunk, so at completion the tracker was still collecting,
  `take()` handed back the empty window, and the result was `$ node …` with no body.
  The tracker is now fed from `onWillData`, before xterm parses the chunk (#181)

- The scratchpad tools appear in the transcript. `write_scratch` and
  `delete_scratch` were missing from the chat's tool-component maps — `.tsx` is
  outside the type-checked `include`, and the lookup is optional — so the call
  succeeded and rendered nothing. Both now render the file name and folder, the
  absolute path on success, and the error text on failure; the scratchpad scenario
  asserts the row exists (#182)

- Terminal launches no longer fail after a few shell exits. `node-pty`
  1.1.0-beta33 leaks about eight file descriptors per shell exit; the pty host
  exhausts the 511-handle `ptmx` table (505 of 511 was observed) and `posix_openpt`
  fails, surfacing as `posix_spawnp failed.` with no hint of the cause. The
  dependency goes to 1.2.0-beta.15 (resolving to 1.2.0-beta.18), whose own write path
  also lets the macOS `fs.write()` workaround — and the partial-write retry layered
  on it — be removed (#178)

**New**

- An editor thread that was never mirrored now reaches the external surface on its
  own. When a turn completes on a thread with no bound conversation, the service asks
  the proxy to create one and delivers the finished final into it; the binding is
  remembered across restarts, so a restart re-confirms it instead of minting a
  duplicate. Binding a thread that already has history no longer replays its tool
  statuses or parked approvals — an old `tool_request` could otherwise be rejected by
  an approval timeout the moment it was adopted (#173)

- Mirrored conversations start with the user's message rather than a synthetic
  "Mirrored Void chat" anchor, and messages typed in the editor are echoed into the
  conversation as the channel user, so the external surface sees questions as well as
  answers. Both are marked processed so they are never dispatched back, and the echo
  scan is floored at binding time so history is not replayed (#177)

- The agent compacts before a request that would not fit, including mid-turn. The
  trigger is the smaller of 20% of the model's context window and 30k tokens; it is
  the manual button's operation and settings run inline — no queued-message hand-off
  — at most once per run, and it fails open: a failed pass logs and sends the request
  unchanged rather than blocking the turn (#176)

- The agent can delegate a self-contained task to a child agent and get a bounded
  report back. The child is an ordinary thread carrying a parent link, run through the
  same loop, so approvals, cancellation, compaction and persistence are inherited
  rather than reimplemented. It returns `status`, a summary capped at 12,000
  characters, the files it actually changed and its usage — never the transcript,
  because the parent re-sends whatever the result carries on every later turn. Depth
  stops at 1, and the child is not adopted as the user's new chat, not re-tagged to
  the window in front, and not sent to the title generator. Exposed as
  `run_subagent`, with `send_message` and `list_children` (#180)
