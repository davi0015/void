**New**

- **Subagents run beside you, not in front of you.** `run_subagent` returns a handle as
  soon as the child exists and is running, so several spawns in one turn start together
  instead of one full runtime apart, and a long child no longer holds your turn or your
  next message. `collect_subagent` is the join: it takes one or more handles (ids or the
  aliases you coined), waits up to `timeout_seconds` for them to settle — default 60,
  maximum 300, `0` reports the current status without waiting — and returns each child's
  status with the settled ones' reports. `cancel_subagent` stops one child and reports
  `cancelled` rather than `rejected`, because "the manager decided" and "something else
  stopped it" are different facts. Stopping your turn now stops the *wait*, never the
  children: they keep working and their reports are still there at a later collect. A
  child whose window closed mid-run reads `interrupted` after a restart instead of a
  `running` that never resolves, and the next turn's context lists each subagent with its
  status and whether its report has been collected (#191)

- **A running subagent shows what it is doing, and its row is the way in.** The spawn row
  used to render a bare header while the child's own thread — what it is doing right now
  — was already in memory, and the only door into a child was its notification. The row
  now shows the child's live state, opens its transcript, and the report arrives
  collapsed rather than expanded (#185)

**Fixes**

- **A chat you scrolled up in stays where you put it.** The transcript followed the bottom
  only while the reader was "at the bottom" — but that was a 100 px band, and three paths
  scrolled on it: every streaming token, any content resize (a code block swapping to an
  editor), and an appended row. Scrolling up from the last message therefore did not
  survive the next token, which moved the viewport a whole screen in the measured case. The
  pin is now explicit: set only at the actual bottom, released by the first upward
  movement (including a wheel heard before the browser moves), and sending a message
  scrolls to the bottom deliberately instead of relying on the pin (#195)

- **A scratch file stays out of the review queue whichever tool writes to it.** `write_scratch`
  already wrote past the diff service, because a probe script is not a project change — but
  `edit_file` or `rewrite_file` on a path under `.void/tmp` took the ordinary route, so the
  file appeared among the changes waiting for accept or reject. A scratch change is now
  accepted as it applies, in every apply path: the edit still lands, the scratch limits are
  unchanged, and nothing is left for you to review (#194)

- **The compaction status belongs to the thread being compacted.** The chat pane is reused
  across tab switches, so after starting a compaction in one thread every other thread's
  composer showed "Compacting..." with its Compact button disabled until the summarisation
  finished. The status is now keyed by the thread that started it, and a switch clears the
  dialog, the failure message and the "kept N messages" line with it (#193)

- **Settings stop reverting a moment after they are set.** A reload triggered by the
  storage echo could read the blob *before* a write and adopt it after, undoing a setting
  that was already persisted; the next write then persisted the reverted value. The read
  is now bracketed by a write generation, so a read that spans a write is dropped. This
  was also what swapped a chat's model back to the previous tab's shortly after a tab
  switch (#188)

- **Auto-compaction sizes the request by what the provider reported, not by an estimate
  of the conversation.** The trigger took the larger of the last request's token count
  and a chars/token estimate of the live view, so an estimate could outvote an exact
  number and compact a thread with most of its window unused — a 650k-window thread at
  450k. The provider's `input + output` is the size of everything about to be resent; the
  estimate now only covers the two moments there is no count (a thread's first request,
  and the one right after a compaction) (#189)

- **A chat shows the model its last message was actually sent with.** Two writers treated
  the saved selection as "whatever the dropdown shows", so a model picked and never sent
  with replaced the record of the last run, and a chat with no record had one fabricated
  from whichever tab had been visited before it (#187)

- **`read_terminal` accepts the id `open_persistent_terminal` returned.** It took a
  display name only, so the documented follow-up was impossible and a shared display name
  could read another terminal's scrollback. `run_persistent_command` with
  `interrupt_first` now sends Ctrl-C before the command, which is the only remedy for a
  shell stuck at a continuation prompt (#186)

- **A subagent no longer announces that it finished.** A child thread is not a conversation
  the user opened, so it has nothing to announce — the parent is still working, and the row
  that spawned it is where the child is read. The suppression existed at one of the four
  paths that reach the completion notification, so a child that paused for approval and
  then resumed fired "Void finished" for a thread with no tab, and the unread dot was
  missing the same guard. Both now classify the thread in the wrapper rather than at each
  call site (#185)

- **External chat stops loading every bound thread when the proxy reconnects.** The scan
  floor called `getThreadWithMessages` for every `conversationBound`, and the proxy
  re-binds every conversation on each reconnect, so a restart dragged all bound threads'
  history into memory — fourteen bindings, one thread alone 102 MB — and left the renderer
  unresponsive for 4–19 s. It was also wrong: an unloaded thread reads as length zero, so
  the floor landed at 0 and the next turn replayed its entire history through the scans.
  The floor is now established lazily on the thread's first running tick (#184)

- **An external-chat final held while the conversation was unbound expires.** A turn that
  finished while the proxy was down or the session mirror was empty held its final
  forever, and a daemon restart days later posted it as if it were new. Held finals are
  dropped after ten minutes instead of delivered (#184)

**Known limits**

- A child cannot be steered mid-run. `send_message` refuses a child that is still
  running; steering between its tool calls is the next step (M4)
- The subagent surface is one row per child: no tree, no aggregate status, and approving
  a tool from a non-visible child's transcript is M3.5
- There is no concurrency cap, and the 500 ms write-coalescing window under a fan-out is
  unmeasured — the design says measure before adding a limiter
